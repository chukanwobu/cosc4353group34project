2. Design and Development Methodology

Methodology Evolution

Our team continues to utilize an Agile development methodology with Scrum sprints, building directly upon the architectural foundations established in Assignment 1 (A1). While A1 focused on high-level system boundaries, key domain actors (Students, Staff, Administrators), and external integration points (such as the notification service), Assignment 2 translates those abstract specifications into a fully interactive, component-driven front-end user interface.

Sprint Focus & Task Division

To manage project scope effectively across our four team members, we partitioned the application into four modular functional domains: User Authentication & Personal Dashboard, Queue Interaction & Status Tracking, Administrative Services & Controls, and Queue Control & Notification Engine. Each team member assumed complete ownership of their assigned domain, guaranteeing consistent UI styling, modular TypeScript code architecture, and clear separation of concerns.

3. Front-End Technologies and Responsibilities

Technology Stack & Justification

  • Framework / Library: React 19 (with TypeScript) – Chosen for component-driven architecture, declarative rendering, robust type safety, and seamless state management via React Context (QueueContext).
  • Build Tooling: Vite 8 – Provides ultra-fast Hot Module Replacement (HMR) and optimized build pipelines.
  • Routing: React Router DOM v7 – Enables clean client-side SPA navigation between User and Admin roles.
  • Styling & Responsive Design: Modular CSS & Flexbox/Grid – Ensures total visual consistency, clean card layouts, and mobile-to-desktop responsiveness.
