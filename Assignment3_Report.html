2. Backend Technologies and Architecture Justification

Selected Technology Stack

  • Language & Runtime: Node.js (v20+ LTS) with TypeScript
  • Framework: Express.js (v4.21+) with cors middleware
  • Testing Framework: Vitest & Supertest (v8 coverage provider)

Architectural Justification & Alignment with QueueSmart

  • Modular REST API Design: Express.js provides a lightweight routing pipeline separating the application into distinct domain controllers (authController, serviceRoutes, queueRoutes, historyRoutes, notifRoutes). This directly implements the system boundaries specified in Assignment 1 and services the screens built in Assignment 2.
  • In-Memory Data Structures: In strict accordance with Assignment 3 specifications, all state is maintained in TypeScript in-memory collections (server/src/data/memoryStore.ts), intentionally deferring persistent database configuration to Assignment 4 while guaranteeing sub-millisecond execution speeds and zero external setup barriers for unit tests.
  • Payload Validation & Type Safety: Defensive boundary validation validates all incoming payloads (e.g., email syntax, password complexity, the mandatory 100-character upper limit on service names, and 200-character limits on queue notes), returning standardized HTTP status codes (201 Created, 200 OK, 400 Bad Request, 401 Unauthorized, 409 Conflict).
  • Front-End Integration: The A2 React/TypeScript front-end connects directly to these backend endpoints via asynchronous HTTP services (src/services/authApi.ts), allowing real-time authentication, session persistence, and role-based views to reflect live backend data.
